# Release Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every merged release PR publishes prebuilt `tdo` binaries on a GitHub release, installable
with `mise use -g github:bwilczynski/twydo`.

**Architecture:** A port of unifictl's pipeline (`~/Projects/homelab/unifictl`, read it for any
detail this plan leaves open). Four workflows: `ci.yml` (reusable: `mise run lint`, `mise run
test`), `pr-validation.yml` (CI plus commitlint on PR title and commits), `release-plz.yml` (on
push to `main`: keeps a release PR open with the version bump and CHANGELOG, and tags `vX.Y.Z`
when it merges), and `release.yml` (generated by cargo-dist: on a version tag, builds archives on
native runners and creates the GitHub release).

**Tech Stack:** GitHub Actions, mise (`jdx/mise-action@v4`), release-plz (`release-plz/action@v0.5`),
cargo-dist 0.33.0, commitlint (`@commitlint/config-conventional`).

**Spec:** none separate; the design was agreed in chat on 2026-11-03: copy unifictl, adapted to
twydo's workspace; first release cut as soon as the pipeline merges (the repo
is public).

## Global Constraints

- Default branch is `main` (renamed from `master` on 2026-11-03, before this work).
- One version and one tag for the whole workspace: `v{{ version }}`. `twydo-core` is never tagged or
  released separately. The version stays in `[workspace.package]`.
- First release: `0.1.0` (the current workspace version).
- Targets, built natively, as unifictl: `aarch64-apple-darwin` on `macos-15`, `x86_64-apple-darwin`
  on `macos-15-intel`, `aarch64-unknown-linux-gnu` on `ubuntu-24.04-arm`, `x86_64-unknown-linux-gnu`
  on `ubuntu-22.04`. Archives only (`installers = []`).
- cargo-dist `0.33.0` (same as unifictl; known good). Rust `1.99.0` stays pinned in both
  `mise.toml` and `rust-toolchain.toml`.
- release-plz: `git_only = true` (nothing goes to crates.io), `git_release_enable = false` (dist
  creates the release), `release_always = false`, `release_commits = "^(feat|fix)"`, and
  unifictl's changelog groups.
- Tag pushes use the `RELEASE_PLZ_TOKEN` secret (a PAT), because tags pushed with `GITHUB_TOKEN` do
  not trigger `release.yml`. The repo has no secrets today; the user adds it (Task 5).
- No agent attribution in commits or the PR description (user's global rule).
- Docs change in the same commit as behaviour; `python3 tools/check_links.py` must pass.

## Review Focus

1. **mise picks the wrong binary or none.** The repo is `twydo` but the binary is `tdo`; mise's
   github backend must still put `tdo` on PATH. Checked after the first release (Task 5, step 6);
   if it needs an option (e.g. `bin=tdo` / `rename_exe`), the docs carry it.
2. **Two tags or a `twydo-core` tag.** release-plz must produce only `v0.1.0`. Checked by the local
   `release-plz update` run in Task 4.
3. **Core-only changes missing from the changelog.** A `fix(core)` touching only
   `crates/twydo-core/` must still bump the version and appear in `CHANGELOG.md`
   (`changelog_include`). Checked in Task 4.
4. **Docs-only or tools-only merges opening a release PR.** `docs:`/`chore:` commits must not
   (`release_commits`). Checked in Task 4.
5. **macOS build breaks only at release time.** CI runs on Linux only, so a macOS compile error
   first shows in `release.yml`. Mitigation: `release.yml` also runs `dist plan` on PRs; the first
   tag is watched (Task 5) and a failed macOS build is fixed before announcing the install command.

### Task 1: mise tasks and package metadata

**Files:**
- Modify: `mise.toml`, `Cargo.toml`, `rust-toolchain.toml`

**Interfaces:**
- Produces: `mise run lint`, `mise run test`, `mise run build`, used by `ci.yml` (Task 2).

- [ ] **Step 1:** In `mise.toml` set `rust = { version = "1.99.0", profile = "minimal", components = ["clippy", "rustfmt"] }`,
  add `cargo-dist = "0.33.0"` and `release-plz` (latest from `mise ls-remote release-plz`, pinned),
  and tasks:
  - `build = "cargo build --release"`
  - `test`: `cargo test --workspace`, then `python3 -m unittest discover -s tools/tests -t .`, then
    `python3 tools/check_links.py`
  - `lint = "cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check"`
  Keep `demo` and the vhs/ttyd tools and their comment. Add `profile = "minimal"` to
  `rust-toolchain.toml` and a comment that it must match `mise.toml` (unifictl has the wording).
- [ ] **Step 2:** In `[workspace.package]` add `repository = "https://github.com/bwilczynski/twydo"`
  and `description = "Terminal task app that shares its tasks with 2Do"`; inherit both
  (`.workspace = true`) in `crates/tdo/Cargo.toml` and `crates/twydo-core/Cargo.toml`. Add to the
  root `Cargo.toml`:
  ```toml
  # The profile that 'dist' will build with
  [profile.dist]
  inherits = "release"
  lto = "thin"
  ```
- [ ] **Step 3:** Run `mise install && mise run lint && mise run test`. Expected: all pass. If a tool test
  needs something a stock Ubuntu runner lacks (e.g. vhs), say so in the report; do not skip it silently.
- [ ] **Step 4:** Commit: `build: add mise lint, test and build tasks`.
