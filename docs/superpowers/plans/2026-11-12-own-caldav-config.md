# Own CalDAV config, `tdo config init` / `check` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Twydo's `config.toml` holds the CalDAV connection, Twydo generates the vdirsyncer
config itself, and `tdo config init` / `tdo config check` guide a new user to a working setup.

**Architecture:** A new `twydo_core::sync::vdirsyncer` module renders the vdirsyncer config from
`[sync]` and keeps it current under the per-vdir state dir. The sync runner, conflict hook,
reconcile code and list helper use its fixed names and path instead of the removed `pair`,
`local_storage` and `vdirsyncer_config` keys. Removing those keys from the wire `Config` is a
protocol break, so the protocol generation goes to 2 first. The `tdo config` commands live in
the `tdo` crate, read and write the file directly (no daemon), and edit it with `toml_edit`.

**Tech Stack:** Rust (workspace crates `twydo-core`, `twydo-daemon`, `tdo`), `toml`,
`toml_edit`, `serde_json` (for vdirsyncer value quoting), new dependency `shell-words` in `tdo`.

**Spec:** `docs/superpowers/specs/2026-11-12-own-caldav-config-design.md`

## Global Constraints

- No personal data in the repository: tests use synthetic URLs (`https://dav.example.test/…`),
  usernames (`alice`) and commands (`["pass", "show", "twydo/caldav"]`).
- Tests isolate both `XDG_CONFIG_HOME` and `TWYDO_SOCKET`; stop only an isolated test daemon.
- Never put a cargo target dir in `/tmp`; if a second one is needed, use `~/.cache/<name>`.
- Fixed names: pair `twydo`, local storage `twydo_local` (`b`), remote storage `twydo_remote` (`a`).
- Generated hook: `conflict_resolution = ["command", "tdo", "conflicts", "hook"]`; metadata
  `["displayname", "color"]`; collections `["from a", "from b"]`.
- Generated file: `<vstate>/vdirsyncer/config`; `status_path = "<vstate>/vdirsyncer/status/"`,
  where `<vstate>` = `store::bind_vdir_state(&cfg.state_dir(), &cfg.vdir)`.
- First line of the generated file: `# Generated by Twydo from config.toml; do not edit, it is overwritten.`
- Removed keys `pair`, `local_storage`, `vdirsyncer_config`, `after_edit` are a config error:
  `[sync] <key> is no longer supported: Twydo generates the vdirsyncer config; run `tdo config init``.
- Missing required key: `[sync] <key> is required; run `tdo config init`` for `url`, `username`,
  `password_command` (an empty array counts as missing).
- Supported vdirsyncer: `0.21.x`, for both `[sync].command` and `[sync].list_python`.
- `config check` and `config init` never contact the server.
- Exactly one commit is breaking: Task 3's, `feat(config)!:` with a `BREAKING CHANGE:` footer.
- Commit messages carry no agent attribution lines.
- Full gate before the final task's commit: `mise run test` and `mise run lint`.

## Review Focus

1. Password command words containing quotes, backslashes or spaces must survive into the
   generated `password.fetch` unchanged (test in Task 1).
2. A `config.toml` that is a **relative** stow symlink must stay a symlink after `init`, with
   the target file rewritten (test in Task 5).
3. A vdir given as `~/…` must be written `~`-relative in `config.toml` but absolute in the
   generated `path` (tests in Tasks 1 and 5).
4. The user's current production config (`[sync]` with only old keys plus `command`,
   `list_python`, list prefs, comments) must come out of `init` with the old keys gone and
   everything else intact, and must prompt for `url` with no default (test in Task 5).
5. `config check` on a machine where the vdir was never bound must not create the state dir
   (test in Task 4).

- Produces:
  - `#[derive(clap::Args)] pub struct InitArgs { #[arg(long)] no_sync: bool, #[arg(long, conflicts_with = "no_sync")] url: Option<String>, #[arg(long, conflicts_with = "no_sync")] username: Option<String>, #[arg(long, value_name = "CMD", conflicts_with = "no_sync")] password_command: Option<String>, #[arg(long, value_name = "PATH")] ca_file: Option<PathBuf> }`.
    The vdir answer comes from the existing global `--vdir`. `--password-command` is one string
    split with `shell_words::split`, like the prompt. *(Plan decision: one string, not `CMD…`.)*
  - `prompt::Prompter` trait: `fn interactive(&self) -> bool; fn line(&mut self, question: &str, default: Option<&str>) -> io::Result<Option<String>>; fn confirm(&mut self, question: &str, default: bool) -> io::Result<Option<bool>>;` — `None` means EOF/Ctrl-C. `TerminalPrompter` uses stdin/stderr and `std::io::IsTerminal`.
  - `init::run(path: &Path, home: &Path, vdir_flag: Option<&Path>, args: &InitArgs, p: &mut dyn Prompter) -> Result<PathBuf, InitError>` — returns the path written. `InitError` covers `Cancelled` (EOF: nothing written), `Required { flag: &'static str }`, IO and TOML errors.
  - `write::write_through(path: &Path, text: &str) -> io::Result<()>`: if `path` is a symlink,
    resolve its target (relative targets against the link's directory, following chains),
    write a temp file in the target's directory and rename it over the target; otherwise the
    same in `path`'s directory, creating the parent dir if missing.
  - `write::home_relative(path: &Path, home: &Path) -> String`: `~/rest` when under `home`, else the path as given.
- Behaviour pins:
  - Defaults come from the raw `toml_edit::DocumentMut` of the existing file (any keys allowed):
    `vdir` (else `~/.local/share/twydo/vdir`), sync on if a `[sync]` table exists, and
    `url`, `username`, `password_command` (shown joined with `shell_words::join`).
  - Prompts: `Vdir`, `Sync with a CalDAV server?` (`[y/N]` or `[Y/n]` per default), then
    `Server URL`, `Username`, `Password command (prints the password, e.g. pass show twydo/caldav)`.
    Empty answer with a default takes the default; empty without one re-prompts; an unbalanced
    quote in the password command re-prompts.
  - Precedence per value: flag, then (interactive) prompt with existing value as default, then
    (non-interactive) existing value, then default; a required sync value still missing
    non-interactively → `InitError::Required` naming the flag (`--url`, `--username`, `--password-command`), nothing written.
  - Edit: set `vdir`; with sync, set `[sync].url`, `.username`, `.password_command` (array),
    `.ca_file` only if `--ca-file` given; remove `pair`, `local_storage`, `vdirsyncer_config`,
    `after_edit`; without sync, remove `[sync]`. Leave every other item and comment as it was.
  - After writing: print `wrote <path>` to stderr, create the vdir dir (`create_dir_all`, expanded),
    run and print `check::run`, and if `client::probe` says `Running`, print
    `restart the daemon to apply: tdo daemon stop` to stderr. Exit code = check's.
