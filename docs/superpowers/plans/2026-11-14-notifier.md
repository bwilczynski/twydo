# Notifier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Desktop reminders from the daemon on Linux and macOS: every alert and timed due as its
own notification, date-only and overdue tasks in one morning digest.

**Architecture:** A pure planner in `twydo-core` (`remind`) turns a snapshot, the sent keys and
"now" into the deliveries that are due and the next wake instant. A notifier thread in
`twydo-daemon` calls it, runs a platform command through a `Sink`, and records successes in
`notifier.json` in the per-vdir state directory.

**Tech Stack:** Rust workspace (`twydo-core`, `twydo-daemon`, `tdo`), chrono/chrono-tz, serde,
no new dependencies.

**Spec:** [docs/superpowers/specs/2026-11-14-notifier-design.md](../specs/2026-11-14-notifier-design.md)

## Global Constraints

- The notifier never writes a task file. The daemon log names UIDs and keys only, never titles.
- No test may reach a real notification service: `DaemonOptions::new` has no sink; only the
  `tdo daemon` binary selects the platform sink, and `TWYDO_NOTIFIER=off` (set by every test
  helper that spawns `tdo`) stops it from doing so.
- `twydo-core::remind` does no clock, file or process access (like `views`).
- Fixtures are synthetic; no personal data (AGENTS.md ground rules).
- Commits pass commitlint (`type(scope): subject`, lowercase subject start, header ≤ 100
  characters, body lines ≤ 100) and carry **no** agent attribution or `Co-Authored-By` trailer.
- Never put a cargo target directory under `/tmp`; use the default `target/`.
- Each task ends green on `cargo test -p <crate it touched>`, `cargo fmt --check` and
  `cargo clippy --workspace --all-targets -- -D warnings`.
- Protocol additions are additive only; `schema/tdo.openrpc.json` is regenerated with
  `tdo daemon schema` when the protocol changes (`crates/twydo-daemon/tests/schema.rs` checks).
- Defaults from the spec: catch-up 24 hours, delivery timeout 10 seconds, digest lists at most 5
  titles, retry backoff 5 s doubling to a cap of 300 s, wait cap 5 s.

## Review Focus

Inputs the spec does not name; each is pinned by a test in the task shown.

1. A title starting with `-` (or containing quotes or newlines) must not be read as an option
   by the notification command: arguments are passed after `--` where the tool supports it
   (Task 4).
2. A title containing `&`, `<` or `>` must show literally: mako renders markup in the body, so
   the Linux sink escapes the body (Task 4).
3. An empty title must still notify (`notify-send` refuses an empty summary): it becomes
   `(untitled)` (Task 3).
4. A state file that cannot be saved after a delivery must not cause a redelivery every wake:
   the in-memory record is authoritative while the daemon runs, and the failure shows as
   `notifier_error` (Task 5).
5. A notification command that hangs must be killed at the timeout, count as a failure, and
   not delay daemon shutdown beyond it (Tasks 4 and 5).

**Interfaces:**
- Consumes: `Snapshot`, `Task`, `Alarm`, `Trigger`, `IcalDateTime::resolve`, `Status`, `TaskKind`.
- Produces:

```rust
/// What fired at an instant.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Cause { Due, Alert { index: usize } }

/// One instant of one task with everything that fires then (never empty), in the order
/// Due first, then alerts by index.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Timed { pub at: DateTime<Utc>, pub causes: Vec<Cause> }

/// Open, list neither hidden nor archived, not a child of a checklist.
pub fn eligible(snap: &Snapshot, idx: usize) -> bool;

/// The task's timed triggers, coalesced by instant, ascending.
pub fn timed(task: &Task, tz: Tz) -> Vec<Timed>;
```

Rules (spec "Triggers"): absolute alert → its instant. Relative alert → anchor + offset; the
anchor is `due` when `related_end` or the task has no `start`, else `start`; no anchor value →
no trigger. A date-only anchor is local midnight of that date in `tz`. Due with a time → its
instant (`Cause::Due`); a date-only due yields no `Due` cause. A local time that does not exist
or is ambiguous (DST) resolves the way `IcalDateTime::resolve` does; for local midnight use
`earliest()`, falling forward one hour when the time does not exist.

  - `relative_alert_without_anchor_yields_nothing`.

### Task 3: The planner, the digest and notification text

**Files:**

**Interfaces:**

- Produces:

```rust
pub struct Settings { pub tz: Tz, pub morning: NaiveTime, pub catch_up: chrono::Duration }

impl Settings { pub fn from_config(cfg: &Config) -> Settings; }  // tz = cfg.tz()

/// Key → when it was sent.
pub type Sent = BTreeMap<String, DateTime<Utc>>;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Delivery { pub key: String, pub uid: Option<String>, pub title: String, pub body: String }

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Plan { pub due: Vec<Delivery>, pub next_wake: DateTime<Utc> }

pub fn plan(snap: &Snapshot, sent: &Sent, now: DateTime<Utc>, s: &Settings) -> Plan;
```

Fixed values:
- Timed key: `t:<uid>@<instant as RFC 3339 UTC, seconds, "Z">`, e.g.
  `t:u1@2026-11-16T13:30:00Z`. Digest key: `d:<YYYY-MM-DD>` (local date). `uid` is `None` for
  the digest.
- `due` holds every timed trigger of an eligible task with `now - catch_up < at <= now` whose
  key is not in `sent`, ascending by instant then UID; then the digest for today's local date
  when local `now` is at or past `morning`, its key is not in `sent`, and it is not empty.
- `next_wake`: the earliest of every trigger instant `> now` and the next digest instant
  (today's `morning` if still ahead, else tomorrow's; a nonexistent local time falls forward
  as in Task 2). Always in the future.
- Timed text. Title: the task's title, or `(untitled)` when empty or whitespace. Body: parts
  joined with ` · `: (1) `describe_alarm` of the first alert cause, only when the causes do not
  include `Due` and that alert's instant is not the task's due instant; (2)
  `Due <relative_date(due, now in tz)>` when the task has a due value; (3) the list's display
  name, else its id.
- Digest. Due today: eligible, due is date-only and equals today. Overdue: eligible, due date
  before today, or due instant `< now`. Title: `N due today, M overdue`, `N due today`, or
  `M overdue`. Body: one title per line (same `(untitled)` rule), due-today first then overdue,
  each group by due ascending then title, at most 5 lines, then `+K more` when more remain.

- Produces:

```rust
// DaemonOptions
/// The platform sink; `None` (the default) leaves the notifier idle unless
/// `[notifications] command` is set.
pub notify: Option<Arc<dyn notifier::Sink>>,

// notifier/mod.rs — shaped like schedule::Scheduler
pub const MAX_WAIT: Duration = Duration::from_secs(5);
pub struct Notifier { /* … */ }
impl Notifier {
    pub fn start(shared: Weak<Shared>, clock: Arc<dyn Clock>, sink: Option<Arc<dyn Sink>>) -> Notifier;
    pub fn poke(&self);
    pub fn stop(&self);          // idempotent, joins the thread
    /// The sink in force for `cfg`: its `command` if set, else the option's sink.
    pub fn sink_for(&self, cfg: &Config) -> Option<Arc<dyn Sink>>;
}

// StatusView
#[serde(default, skip_serializing_if = "Option::is_none")]
pub notifier_error: Option<String>,
// Publisher
pub fn set_notifier_error(&self, e: Option<String>);   // like set_drain_error

// DaemonHandle, #[doc(hidden)]
pub fn poke_notifier(&self);
```

Behaviour:
- Started after the daemon is ready, next to `start_scheduler`, always (also with
  `schedule: false`), using `opts.clock`. Stopped in teardown where `stop_scheduler` is, before
  the state directory lock is released.
- `Shared::poke_scheduler` also pokes the notifier (it already runs after every publish and
  sync end); a configuration reload pokes it too.
- Each wake: read `publisher.config()`; `enabled == false` or no sink → wait. Otherwise plan on
  `publisher.current()` and deliver `plan.due` in order. Success: `SentState::record`, clear
  `notifier_error`. A save error keeps the key in memory and sets
  `notifier_error = "cannot save reminder state: …"`. Delivery failure: set
  `notifier_error = "cannot deliver reminders: …"`, log the key (no title), stop this pass and
  retry after the backoff (5 s doubling to 300 s, reset on success). After each change call
  `publisher.refresh_status()`.
- Wait until the earliest of `plan.next_wake`, the retry time and `MAX_WAIT`, re-reading the
  clock on every wake; a poke wakes it at once.
- Lock order: the notifier holds none of its own locks while it plans, runs a command or
  touches the publisher.
