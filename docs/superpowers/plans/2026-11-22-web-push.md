# Web Push Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server's notifier pushes every reminder to each phone that turned reminders on, so
Twydo can replace 2Do's reminders on the iPhone.

**Architecture:** The daemon's existing command sink runs a new `tdo gateway push`, which reads
the gateway's VAPID key and per-device push subscriptions, encrypts the reminder (RFC 8291),
signs a VAPID JWT (RFC 8292) and POSTs it to each push service. Its exit status feeds the
notifier's existing retry and `notifier_error`; the error reaches the phone through `views.get`.
The PWA subscribes from a switch in the Views tab and its service worker shows the notification.

**Tech Stack:** Rust (twydo-daemon, twydo-gateway, tdo), RustCrypto `p256`/`hkdf`/`aes-gcm`,
`ureq` 3 with rustls+ring (already in the tree via twydo-core), TypeScript/Preact/Vitest in `web/`.

**Spec:** [docs/superpowers/specs/2026-11-22-web-push-design.md](../specs/2026-11-22-web-push-design.md)

## Global Constraints

- The daemon gains no network, HTTP-client or Web Push code (only §5 env vars and §6 field).
- No task title, body, note or full endpoint URL in any log line or error text; log the device
  name, the endpoint's host and the status code.
- Pure-Rust TLS only: reuse `ureq` `~3.5` with `rustls-no-provider`, `_ring`, `platform-verifier`
  as `crates/twydo-core/Cargo.toml` does. No OpenSSL.
- Crypto from RustCrypto primitives (`p256` with `ecdh` and `ecdsa`, `hkdf`, `aes-gcm`, and the
  `sha2` already in the tree); pick mutually compatible current releases with `cargo add`. No
  hand-written primitives; only the RFC 8291/8292 glue.
- Gateway state files: 0600 in a 0700 directory, written under the `devices.lock` flock with the
  existing atomic replace (`Store::modify`).
- Protocol stays generation 4; `views.get` change is an optional field.
- `TTL: 86400`, `Urgency: high`, overall push deadline 8 s (the sink kills at 10 s).
- Commit messages pass commitlint (`type(scope): subject`, lowercase subject, ≤100 chars).
- Tests isolate `XDG_CONFIG_HOME`, `XDG_STATE_HOME` and `TWYDO_SOCKET`; no real push service
  and no real notification is ever reached from a test.
- Cargo target dir must not be under `/tmp` (quota tmpfs); use the default or `~/.cache`.

## Review Focus

1. **A push racing a re-subscribe:** the phone PUTs a new subscription while `tdo gateway push`
   gets `410` for the old one; the new one must survive. Test in Task 4 (`remove_dead_keeps_a_newer_subscription`).
2. **A title that does not fit the padding bucket** (long title, long body, multi-byte text):
   the payload must still encrypt to the fixed size, cut on a char boundary, never panic. Test in
   Task 3 (`payload_cuts_long_text_on_char_boundaries`).
3. **A revoked device's subscription** must not receive the next reminder. Test in Task 4
   (`revoke_drops_the_subscription`).
4. **A hung push service** must not keep `tdo gateway push` past the deadline, and must leave
   the subscription in place. Test in Task 6 (`hung_service_is_cut_at_the_deadline`).
5. **A notification tap while a form is open** must not reload the page. Test in Task 9
   (`open_message_pushes_task_without_reload`).

### Task 3: Web Push message encryption and VAPID (pure)

**Files:**
- Create: `crates/twydo-gateway/src/push/mod.rs`, `crates/twydo-gateway/src/push/crypto.rs`

**Interfaces:**
- Produces (in `push::crypto`):
  - `pub struct VapidKey(p256::SecretKey)`; `VapidKey::generate() -> VapidKey` (via
    `getrandom`, retry until a valid scalar); `from_bytes(&[u8;32])`, `to_bytes() -> [u8;32]`,
    `public_b64() -> String` (uncompressed 65-byte point, base64url no pad).
  - `pub fn vapid_header(key: &VapidKey, endpoint: &str, subject: &str, now: i64) -> Result<String, String>`

  - `pub struct Payload { pub title: String, pub body: String, pub key: String, pub uid: Option<String> }`;
    `pub fn padded(p: &Payload) -> Vec<u8>`: JSON (`uid` omitted when `None`) + `0x02` + zeros

    `fn encrypt_with(plain, p256dh, auth, ephemeral: p256::SecretKey, salt: [u8;16])` (tested
    against the RFC). Output: RFC 8188 header (`salt`, `rs = 4096`, `idlen = 65`, sender key)
    then one AES-128-GCM record; `plain` already ends with the `0x02` delimiter.
